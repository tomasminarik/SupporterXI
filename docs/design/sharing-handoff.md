## 2. What is already decided

From the [PRD](../product/canonical-prd.md) section 6, [application behaviour](../implementation/application-behaviour.md) ("PNG export"), MVP-08 and `AGENTS.md`:

- Output is a real PNG at exactly the chosen size: feed portrait 1080 × 1350 and story 1080 × 1920. A landscape format is wanted, but **its dimensions are undecided** (open product decision); confirm with the user before building it.
- Portrait formats use a bird's-eye portrait pitch. Landscape uses the desktop builder's perspective pitch.
- Only a complete, structurally valid XI can be exported. An incomplete XI cannot produce a final image.
- The image includes fixture context, formation, players and pitch. **Roles are excluded from every format.** No club crests, player photographs or licensed kits; original assets only.
- Capture an immutable snapshot of the XI when export starts. Wait for local fonts and assets before rendering. A failed export keeps the working XI and offers retry.
- Download is the baseline. Native file sharing may be offered where the browser supports it, never as the only way.
- No lineup URLs, URL-encoded lineups, shorteners, uploaded images or personalised link previews. Nothing about a supporter's lineup leaves the browser (MVP-14).
- M-02: a selected player who later became unavailable stays in the XI and is exported.
- The entry point is labelled "Share your XI". The product name is Supporter XI; no domain is approved, so do not print a web address on the image without asking.

## 3. Not designed yet

Propose each of these, show it, and let the user decide.

1. **The share flow.** What happens when "Share your XI" is pressed: a dialog with a preview, a format choice and one download button was the direction noted in the design research (Substack and Perplexity share dialogs). On phones a bottom sheet would match the rest of the mobile design.
2. **The button when the XI is incomplete.** Today it is disabled. It needs an honest state and wording ("Pick 3 more players to share").
3. **The image itself, per format.** Layout of the fixture headline, formation name, pitch, eleven players (number and short name), and the Supporter XI mark. The builder's visual language is the starting point: dark page, Big Shoulders Display headline with the club in red, "v" in grey and the opponent in white, red pills with a white number disc.
4. **Landscape size.** Ask the user. Common choices are 1920 × 1080 and 1200 × 675 (16:9) or 1200 × 630.
5. **Long content.** Long opponent names ("Tottenham Hotspur FC" as the provider gives it), unknown kickoff ("Time to be confirmed"), eleven long surnames, players sharing a surname.
6. **Loading, failure and retry states** inside the flow, and focus handling for the dialog.

## 5. Technical notes for whoever builds it

- A recommendation to examine, not a decision: draw the image on a canvas from the snapshot rather than capturing the page. That gives exact pixel sizes, needs no new dependency, and avoids the known trouble that page-capture libraries have on mobile Safari. The cost is that the pitch and markers are drawn a second time. Explain the choice to the user before adopting it, as the architecture record asks for material decisions.
- Wait for `document.fonts` to load the faces used, and for the texture image, before drawing.
- Tests for MVP-08 should decode the produced PNG and check its signature and exact dimensions, check that an incomplete XI is refused, that editing the XI while an export runs does not change the image (snapshot isolation), that a forced failure offers retry and keeps the XI, and that no network request leaves the origin.
- Browser tests run with reduced motion by default (`MOTION=1` turns animations on).
- Stop any dev server on port 3000 before `npm run check`, and revert the change the dev server makes to `next-env.d.ts`.
- `main` receives content commits from the admin and the daily import. Fetch before branching and never overwrite `content/shared.json` with an older copy.
